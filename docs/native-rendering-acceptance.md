## Evidence updates

Local bookkeeping lives at `working/coverage/native-rendering-acceptance.sqlite3`.
Definitions and events are append-only. The workspace, evidence payloads, backups
and catalogs are pinned against cleanup. Git snapshots use small compatibility
references; SQLite preserves the verified original payloads.

Generate a new opening/candidate snapshot without overwriting a previous one:

```sh
python3 tools/reconcile-rendering-dependencies.py --acceptance-only --run-guards \
  --report research/runtime/rendering-acceptance-results-NEW/record.json
```

Use verified local SQLite inputs and the storage guard. This mode validates the
record and prerequisite rules, reviews source/evidence candidates, backs up its
local ledger and returns before original-media/byte analysis. Guards do not
launch the player or establish engine equivalence.

To attach an existing registered evidence item to a specific row, use its actual
configuration ID, requirement ID, evidence ID and a concrete applicability reason:

```sh
python3 tools/rendering_acceptance.py \
  --configuration player-default \
  --requirement journey.cursor-interaction.hotspot \
  --evidence PLAYERMERGE27.storage01 \
  --reason 'Retained cursor/storage interval for current relevance review; two refusals prevent whole-COPY closure.'
```

This example attaches the retained interval as a **candidate**. It verifies the
payload/assertions, preserves its exact identity and records the reason. It does
not declare the source current, justify its configuration applicability or pass
the row. Generate a new snapshot afterward to export the attachment; immutable
older snapshots remain unchanged. Repeated identical attachments are idempotent.
Do not edit SQLite events, historical payloads or old snapshot hashes in place.

In a fresh checkout, resolve the verified SQLite evidence first. Restore the
workspace's events from the desired exported snapshot before adding new candidates:

```sh
python3 tools/rendering_acceptance.py \
  --from-record research/runtime/rendering-acceptance-results-20261030/record-02.json
```

Restoration preserves exact event identities and original observation times,
rechecks attached evidence, and creates a verified local backup. It cannot import
a different dossier or accepted outcomes into this opening workspace. The authored
