## Reproduction and storage

Run from the repository root with the existing storage guard, available local
SQLite inputs and a new report name:

```sh
python3 tools/working-retention.py run --reserve-gib 0.15 -- \
  python3 tools/report-rendering-baseline.py \
  --revision 648ce2191c6b5c5d5b18a2508dcddc2ee6fec7d7 \
  --report research/runtime/rendering-reviewed-baseline-results-NEW/baseline.json
```

The producer records missing configured auxiliary stores and uses available
local readers in the temporary export. Every consumed payload is resolved and
hash-verified; published archive inputs must already be local and verified.
An audit error suppresses all current proof and makes the report unsuccessful.
Source/contract history is preserved without refreshing any old evidence hash.
No original media or executable is consumed.

The first frontier attempt stopped at a missing configured auxiliary database;
its failed [frontier report](rendering-reviewed-baseline-results-20261030/frontier-01.json)
is retained. A subsequent producer setup rejected the tracked `working/.gitkeep`
entry before review; the corrected exporter skips excluded storage and the
regression fixture checks that behavior. Setup failures grant no engine credit.

Generated reports are SQLite references. New evidence and bookkeeping are
retained locally with verified backups; remote publication is a separate
operation. The normal storage reserves apply. This baseline is artifact 1 only:
it does not create a new required-gap register, execution-task graph or final
acceptance decision.
