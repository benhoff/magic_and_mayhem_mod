# Native-only launch contract

The `native-only-rendering-v1` policy makes native graphics selection, startup
capability checks, terminal failures and session outcomes one explicit contract:

```sh
python3 tools/working-retention.py run --reserve-gib 3 -- \
  python3 tools/run-native-owned.py --native-only \
    --prefix working/tests/<stopped-owned-prefix> -- --skip-movies
```

Use a stopped prefix with the repository's matching DirectPlay ownership marker.
Omit `--skip-movies` to select the existing native media adapter. This policy is
an intentional native integration policy for the pinned No-CD build, not recovered
original allocator/renderer semantics or a complete replacement certification.

## Startup

The owner launcher rejects conflicting environment settings and unsupported CLI
modes before staging. It selects owned drawing, mode3 backing, resident World,
continuous V3 commands, glyph takeover and all six guarded producer families.
Only declared presentation/media options and bounded journey controls are allowed.
Direct Qt invocation without the matching owner environment refuses.

Before Wine starts, the owned runner verifies the staging policy, all ten graphics
and menu DLL hashes, their compiler source receipts, glyph takeover and native or
disabled movies. A stale source, missing build closure, mismatched binary, absent
producer or facade without the terminal capability handler refuses. The admission
record binds those source/binary identities to the disposable session. Existing
namespace/device/display containment and fresh route counters remain mandatory.

## Failure and retirement

The Qt session hides original-menu fallback and refuses original-presentation
fallback. Menu/renderer failure records a sticky failed session, clears rendering
and input and force-stops the owned process. Closing a failed launch exits nonzero.
Hard restart requires verified process/renderer retirement, preserves the old
failed generation without rendering credit, then admits a fresh generation.

In this mode the native facade terminates on its explicit `E_NOTIMPL` capability
boundaries before the original application can display an error dialog on the
private server. The32-byte `native-render-capability-refusal.bin` contains DWORDs
`MNMCAP01`, version1, bytes32, HRESULT, source line, launch-local caller and thread.
Busy and invalid-rectangle/key errors retain their normal application ABI.
Ordinary non-strict launches retain the previous unsupported-result behavior.

Normal completion requires the original Quit acknowledgement, successful launcher
exit and renderer retirement. The shell atomically records its outcome in the
session's `native-only-session.json`; an earlier failure cannot become success.
The owner independently requires matching admission/shell identities, original
exit0, all43route installation counters, zero forwarding/history refusal, no
terminal artifacts and balanced resident World retirement. Missing or corrupt
records refuse even if Qt exited0. A restarted generation instead requires an
explicit restart request, verified renderer/process retirement and a dead matching
host runner identity (including start ticks); it receives no normal-completion or
rendering credit. The launch requires exactly one normally completed final
generation. No positive route/World minimum is invented
for a user who quits directly from the menu.

## Scope and remaining work

A passing outcome means the declared native-only policy was enforced for that
session. It does not promote `complete_replacement`, original pixel equivalence,
all-game reachability or performance. All43optional handlers exist; five natural
callers remain unresolved. Incoming shared code now implements the checked533aec
row body natively, canonical format/stretch conversion and an owned active-Lock
reader continuation outside exception dispatch. Their original comparison and
broader caller/lifetime evidence are independent of this launch contract. Unadmitted
access/resource domains still refuse; no whole-game instruction census is inferred. Original-reference backing-alias
and global-presentation gates are independent of native-output containment.

Current controls and any bounded original-game acquisition are registered under
`NP.native-only-launch-contract`; historical ownership results retain their hashes
and scope. Wider journeys, media/storage/restart composition and hardware cadence
remain separate validation requirements.

## Glyph refusal closure

A code review found that takeover alone still returned0 on rejected glyph input,
allowing the original glyph body to run. Native-only mode now requires uncaptured
resident takeover at runtime and terminates every such refusal, including busy,
wrong-owner, invalid-input and post-close cases. The ordinary shadow/takeover
profiles retain their existing admission behavior. `native-glyph-forward-refusal.bin`
is32bytes: magic`MNMGLRF1`, version1, bytes32, refusal reason, thread and two zero
reserved DWORDs. Its presence independently rejects a normal session outcome.
