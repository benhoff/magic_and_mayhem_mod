# Hybrid evidence custody — 2026-11-13

The user explicitly authorized aggressive disk reduction and reducing the former
two-copy requirement. Essential evidence retains two verified copies. Explicitly
reviewed historical bulk retains one verified primary; losing that filesystem can
lose the bulk payload. Reviewed rebuildable temporary output may be discarded
with its reconstruction information and consumer check. Original media, active
inputs, source changes and saves remain protected.

The implementation classifies admitted workspace members conservatively, keeps
anonymous reports and typed SQLite closures mirrored, supports explicit promotion
and prevents ordinary writes from silently demoting essential data. SQLite guards
refuse frozen writers. Sparse-aware verification and completion preserve declared
single-copy custody; restore deliberately selects the primary for bulk.

The migration CLI first writes an exact logical catalog and hash-bound SQLite
plan. Apply requires unchanged catalogs, idle stores, independent filesystems and
space reserves. It decodes and hashes every surviving primary object, constructs
and verifies the essential mirror, then atomically replaces the former mirror.
Failure preserves the old mirror; a prepared replacement is retained for review.
No report hashes or engine statuses are rewritten. Earlier custody receipts still
describe their original operation; current classifications record changed custody.

storage-compaction, cleanup and local-workflow suites. Exact logs and failed test
attempts are retained in SQLite-backed controls-01 evidence. The Cold-main
broader-player pilot additionally scrubbed all 59,373 primary objects and verified

change provides no game execution, acceptance promotion, off-host guarantee or
