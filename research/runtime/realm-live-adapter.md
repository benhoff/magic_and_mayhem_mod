# Experimental settled Realm adapter

The V19 lane is separately enabled by `MNM_EXPERIMENTAL_CAMPAIGN_REALM=1`.
Default launch behavior stays at its existing version. Original Realm custom
tick, resource initialization, drawing, movement, tutorials and transitions
remain active. This is native ingress/presentation policy, not recovered
simulation or a drawing synchronization fix.

Settled admission requires the original Realm receiver/vtable, Main/Realm stack
at depth3/context5, initialized resource name/hit map, a supported original realm
name, bounded visible/wizard/player counts, no tutorial/transition/auxiliary
request, and no automatic battle ingress. Ownership and owned adjacency come
from the same original arrays read by the recovered settled tick. Alternate mode
is excluded. The full bounded hit map supplies display centroids; its cache
retires when the Realm loses engine ownership. It never supplies campaign
availability from the preview catalog. Unknown artwork ordinals use literal
region labels, and flags use a text fallback rather than guessed banner frames.

Region activation rechecks eligibility and physical input at dispatch and again
immediately before the scheduled original tick. It supplies one release latch
and a representable hit-map coordinate, restores physical input after that tick,
and lets the original consume the latch and update destination/Region request.
It does not call an additional tick, grant progress, or write ownership,
destination, experience or knowledge. A changed admission consumes the request
with refusal. Current limitations include real input polling, concurrent input,
travel/cleanup/resource reuse and progressed campaign ownership.

Character/Grimoire/Spellbox entry calls original stdcall callback54fd20 with its
recovered index2/3/1 after callback-object checks. Original custom tick remains
responsible for consuming the auxiliary flag and pushing the destination.
Character uses its existing experimental guards; unsupported book/Spellbox
callers retain original viewport ownership. Direct Realm Cancel, realm switching,
Options mode4 and the preview Research route are not invented callbacks.
Broader Region Entry admission and those destinations are subsequent chunks.

The wire is little-endian/versioned with existing lanes preserved and no pointers.
The 512-byte projection contains twelve header words, nineteen six-word region
rows and eight trailing zero bytes. Readiness, generation, request identity and
engine thread remain part of the existing channel contract. A fresh acknowledged
Realm return can restore native ownership after an original auxiliary screen.

Validation is recorded separately after execution. Private fixtures use
synthetic settled campaign state and stub resource/input/audio/movement/drawing
dependencies while executing unchanged original tick/auxiliary bodies. Qt peers
test the production bridge/session/controller with synthetic engine state.
Neither fixture constitutes real campaign progress, victory, persistence or
native-render live replacement evidence.

The [fresh private result](realm-adapter-private-20261012.json) records four
low/high-resolution owned/adjacent original tick cases, three original auxiliary
callbacks and23 admission/input/map refusals. The original tick and auxiliary
callback bytes remain unchanged. Eleven synthetic Qt wire/session/controller
cases, three companion regressions, PE32 linking and the Qt shell build pass
with stable declared sources/compiler closure and original manifests before/after.
The earlier include/pointer, freestanding-link and peer-field/status preparation
failures retain separate pinned run directories; none is live campaign evidence.
