## Original count driver

World `46b5be..46b5e8` calls brain 0 then brain 1, giving each integer allocation/2.
The executed window comparison supplies both called brains and the continuation;
it does not execute the surrounding World admission, timing or startup logic.
Each `415c40` splits its input into floor(total/2) planning and the remaining
execution allocation. Unused planning is not transferred. The count driver
advances its clock even while disabled.

General, wizard, other and root planning queues run in that priority order and
consume the back of their queue. A spent budget retains phase and source,
including an evaluator that finished on the last unit. An already-installed
source in the general queue skips both planning and its budget check, so it is
removed even with zero planning units. An empty root queue copies the source
manager, while a nonempty queue retains its remainder. Execution copies the
installed map into an empty pending queue, visits ascending task keys, checks
its independent budget first and retains unvisited entries. Bodies may overshoot
that budget. Task-result+14 remains distinct from replacement-invalidation+15.

The bounded whole `415c40` comparison supplies planning, perception, maintenance and
snapshot endpoints. It covers all queue priorities and genuine simultaneous
kind 0 installation/map execution/expiry retirement, with original `419900`,
`4289e0` and `428b40`. Clone/allocation, registration/training/teardown remain supplied
storage services. Real task 6 planning/body composition has the earlier NS83
single-source evidence and the new independent NS86 probe/body/decision evidence.
No one comparison composes the full original multi-source World pipeline.

The native ordinary host uses this count driver with explicit World allocation 64
and only brain 0 work. Its source manager includes both ordinary factions; planning
uses source-manager order and execution uses global serial order. The second
brain's other task families and time/rdtsc mode are not implemented. General `421f70`
work is restricted to the ordinary no-candidate branch: there are no wizards,
controllers are present, and an unparented leaf has no flag 704. Kind 5 admission

The full specialized evaluator remains separate from this fixed branch.

## Three-member source search and geometry

Whole `423590` comparisons extend to grouped 3, grouped 2 plus 1, 1 plus grouped 2 and
three independent roots, supplied finite membership-dependent evaluators, sliced
budgets, maximum/weighted modes and healthy/completed/weighted current and other
tasks. Actual `4284e0`, replacement progress and complete strategic RNG are compared.
Net reset danger and candidate distances are supplied in the decision fixture;
whole `40a760`/`429270` separately compare the native distance producer.

The first partition is not simply half the actors. The original unique-key tree
stores one traversal index per distinct speed, keeping the first at equal speed.
It selects the faster ceil(distinct_speed_count/2) entries, then retains original
source traversal order. The complement is registered for later planning. Merge
search likewise keeps the first source at each equal distance, takes the nearest
two distinct-distance entries and partially shuffles one proposal using a draw
even when only one entry remains. The pinned proposal caps `5c5340`/`5c5344` are 1;
random extra partitions and groups larger than three remain outside admission.

Source centers `40a760` use ordered incremental raw-coordinate means with integer
truncation. Merge distance `429270` wraps horizontal deltas but uses full squared
height. Task memory-center refresh `407c10` also averages raw coordinates, then
normalizes. A new three-enemy case exposed the earlier wrapped-mean shortcut:
x = 27 and x = 4 produce x = 16, not x = 31. The recovered body now follows the original.
Historical comparisons with one live enemy did not exercise this branch.

Weighted source search can retain a shared maximum while choosing a biased merge;
removing that bias can produce a commit score above 1. A separate source-commit
predicate models this observed case. Compared previous stored scores stay in
[-1,1]; future replacement of an installed above 1 score is not admitted here.
The native skirmish intentionally uses maximum selection, retaining that boundary.

