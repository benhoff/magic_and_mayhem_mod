# Experimental campaign Character adapter

V18 extends the V17 menu wire without changing earlier lanes. The 256-byte
Character projection carries parent/depth/context, selected wizard identity,
draft experience, enabled actions and six opening/current/maximum/increment/
decrease/increase rows, plus a bounded original Realm wizard label. No pointers,
host-authored experience grants or submitted stat values cross the channel.

The PE32 adapter requires the current Character20 singleton/final vtable,
initialized and transition/modal-free state, exact Main/Realm/optional Region
stack identities and settled Celtic Realm resources. Fresh Region1 refuses.
Original wizard getter selection is mirrored within its 80-record range and
checked against Realm storage. Opening stats must equal the selected wizard's
unchanged stats; draft experience cannot exceed the opening balance. Each
original button/callback object and action index is checked before dispatch.

Adjust requests call original25..36 only when the current snapshot permits the
step and price. OK/Cancel call original0/1. Original price refresh, drawing,
tick, fade and return remain active. Native input does not mutate draft values
optimistically: each change waits for its acknowledged original snapshot. Parent
return hands ownership to original controls; native Realm navigation and complete
window-close unwind remain pending.

The adapter remains disabled by default. `MNM_EXPERIMENTAL_CAMPAIGN_CHARACTER=1`
selects V18 for dedicated validation. Original Realm labels are displayed without
guessing portrait/progression identity; exact Character label/portrait fidelity
remains a separate boundary. Existing first-region disabling is preserved.

The private reference supplies synthetic settled resources/control ownership
and invokes the actual original price refresh, selection getter and Character
callbacks. Fade alone is stubbed with expected-byte verification. Qt tests use
a synthetic mapped peer and verify wire bounds, stale/duplicate refusals,
authoritative display updates and caller handoff. These are headless checks,
not genuine campaign progression, live ownership or replacement evidence.

Evidence UI50 records the private original getter selecting slot 79 of 80 and
committing an actual original adjustment to that wizard. The getter at
`0x5908e0` scans stride `0x93a`, checking active word +0 and secondary word +8;
its upper byte offset is `0x2e220`. No real 80-wizard campaign is claimed.

## Fixture transaction journeys

The Qt controller disables Character controls while a request waits for its
acknowledgement. Adjust, OK and Cancel acknowledgements must name the exact
requested sequence and original engine thread; a different identity retires
native ownership. An unchanged acknowledgement keeps the request pending.

`tests/character-wire-fixture.hpp` is an explicit synthetic engine peer consumed
by the production bridge, session and controller. It supplies a flat price of
11, an in-memory wizard and settled caller identities. The Qt test exercises
all six buy/refund rows, duplicate clicks, both Realm4 and Region18 callers,
Cancel/reopen rollback, OK/reopen accepted baselines and malformed/stale wire
refusals. Those fixture transactions are headless lifecycle evidence only.
The separate private PE oracle continues to execute actual original pricing,
getter and callbacks; the fixture does not establish original campaign entry,
disk save persistence, real Realm navigation or live replacement.

Disabling a Qt Character page can clear its keyboard focus. The controller now
restores the first action when readiness returns, including a cached snapshot.
This keeps keyboard navigation available after a purchase/refund acknowledgement
even when the host sees the page already reenabled. Synthetic Qt transactions
assert focus after all six purchase/refund pairs from both caller identities
(24 checks); this is a native presentation policy, not original focus recovery.

## Three-realm experimental callers

V20's separate campaign-menu opt-in admits settled original Celtic,Greek and
Medieval Character callers. V18 retains the Celtic-only boundary. Region1
is still refused for Celtic,matching its original disabled Character control;
Greek/Medieval region1 is separately admitted. Snapshot/budget/control/thread
checks and original getter/pricing/adjustment/OK/Cancel bodies remain unchanged.

[UI61](character-three-realms-20261012.json) executes six private original
purchase/refund/Cancel cases across both callers and all three realms,alongside
16 existing guards/slot79/pricing/commit checks and three Qt transaction/focus
regressions. Declared source fingerprints remain stable and both original
manifests pass. This extends headless support,not genuine progressed loading,
caller return,persistence,pause or portrait/art equivalence. Raw current evidence
is `working/tests/character-adapter/run-sii8rj3k`. Older exact results remain
historical; no saved progress or stats are authored by these fixtures.
