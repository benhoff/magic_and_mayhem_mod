# Friendly source and task lifecycle (NS84)

## Scope and evidence boundaries

This milestone owns friendly source forests and their task identities, separate
from the anonymous **enemy memory groups** used by task6. It extends the native
lab from one friendly/one enemy to two friendly ordinary type17 creatures and one
enemy. It implements selected split/merge commits, source maintenance and shared
task execution. The original423590 automatic proposal search and winner selection
remain pending; the native split/merge API requires an already selected proposal.
No score or partition decision is invented to fill that gap.

Existing `AI.owned-source-controller-chain` covers416590 with actual416fe0 and
source traversal/root helpers (NS52). Native setup reuses those primitives: the
first ordinary creature gets a leaf; the next joins the nearest available
same-owner root, creates an anonymous parent when necessary, and transfers an
existing leaf recipient to that parent. Initial registration retains general and
ordinary classifications. The deterministic opaque byte25 tag remains a native
representation policy, not an original-byte equivalence claim.

New behavior IDs are `AI.source-task-ownership`,
`AI.owner-source-group-execution`, and
`NP.owned-friendly-source-continuation`. Their independent comparison and native
integration reports bind prospective contracts and source fingerprints. No full
World/campaign equivalence or live replacement is asserted.

## Native ownership and continuation policy

`NativeOwnerSources` owns source storage, queued notifications, per-root planner
contexts, shared strategic random state and global task serials. Source recipient
handles refer to owned planner slots rather than host pointers. Installed task
accounting is routed from either friendly member through its current source;
split tasks receive their own damage/movement costs. Selected topology changes
retire displaced tasks and restart incomplete candidate epochs. Existing task
selection, DAT inference, memory groups and ordinary count-mode scheduler are
reused within each context. The planner uses all friendly members for group
features and task execution.

These host policies are intentional and are not recovered World equivalence:

- Availability is produced from active health; empty-source tasks are retired.
- Ordinary notifications fold into pending roots, with one root visited per
  frame and authored allocation4. Specialized421f70 work is not implemented.
- Membership changes restart incomplete candidate epochs. Installed accounting
  survives ordinary membership refresh until a selected topology commit retires
  it. Task6 planning requires assigned members in the same region and uses the
  representative actor's regional probe; full per-member original probe
  production is pending.
- Node/context identities are bounded at128, and total CMD1 state at1MiB.
  Tombstones preserve identities; arbitrary unbounded split/merge histories are
  outside this lab admission.

CMD1v17 stores the forest, metadata, actor roots, traversal state, queues,
per-source selectors/probes/tasks, shared RNG and serial counter. Malformed
links/cycles/duplicate members/task serials, orphan tasks, invalid RNG, lossy v16
writes and invalid topology requests refuse. Topology API calls stage changes and
publish only after validation. Version0 requests automatic encoding: source
sessions use17; sessions with no new source fields keep16. Explicit v1-v16
compatibility remains available under its existing loss checks.

Portable input scenario8 records the three-actor owner layout in MNMENC02, so a
fresh process reconstructs the same backend dimensions. Existing scenarios and
the two-actor `run-planner` activation retain their formats. Use:

```sh
native-encounter run-sources INSTALL 0 0 32 32 17 256 OUTPUT.snapshot
native-encounter resume OUTPUT.snapshot 256 RESUMED.snapshot
```

Native validation runs a256-frame formed-group journey and a256-frame lifecycle
journey with an explicit split at32 and merge at96. It checks both friendlies'
orders, concurrent tasks after splitting, shared/nonleader and independent task
credit, pending and active checkpoints, per-slice execution, cold process resumes
before/after topology commits, public CLI identity, legacy planner/event/core
regressions and sanitizer equality. Native continuation is independent of the
isolated original-function comparison; automatic strategic topology search is
still the next missing layer.
