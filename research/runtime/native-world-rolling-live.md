# Guarded original producer to rolling native rendering

This adapter connects the original V3 batch producer to the separately versioned rolling native channel. It deliberately retains the existing finite32-queue original admission,128MiB source journal and original destination protection. It is not an unbounded PE32 producer replacement.

The original waits for its RGB565 reply before it emits the final checkpoint and return. `prepareRollingHandoff` validates the actual batch request against all owned original source records, original queue/canvas/800x600 extent, descriptor checksum, entry/backend, canonical source hash, cumulative count and recovered low16 AX. It builds one complete native packet with an explicit anticipated checkpoint/return. These native closing records are not original acknowledgement. `verifyRollingHandoffReturn` later requires the actual original checkpoint identity and guarded return/count fields. Failure is terminal.

A broker thread reads only source records and batch requests. The GUI consumer independently maps the two-slot channel, retains its CPU/GPU history and resource caches and returns the exact requested canvas extent. Neither reads original destination oracles. Native diagnostic checkpoint files and GPU mirror assertions are separate from native World work. The external capture driver compares all completed canvases; after bypass these original canvases include native writeback, so precise original raster/AX comparison remains an independent requirement.

Before execution: first native World completion500ms maximum, warm native median60ms and original request-to-reply median120ms excluding explicitly measured checkpoint diagnostics. Full diagnostic times remain recorded. Original startup/menus, simulation work, filesystem polling, UI painting, input latency and hardware scanout are not inferred from those bounds. The adapter must complete32 original guarded returns, all source descriptors and checkpoint comparisons with zero retained surfaces. A fixture validates32 captured plans plus256 identity/extent/corruption/return refusals. Separate consumer-death and original-private-Wine-death runs terminate while queue2 is outstanding after native queue1 completion; a later fresh complete session must pass.

Original pointer/lifetime and caller ABI guards remain in the existing PE32 hooks; no original executable bytes or hooks are changed by this adapter. Native packet sequence is independent of original global source-record sequence; original checkpoint identities remain explicit. The finite journal retained by the broker is bounded by the existing contract. Removing that journal and admitting original queues beyond32 is a later original-producer milestone, not established by this bridge.

The first actual live iteration reached queue1 but refused queue2: anticipated closing records had uninitialized reserved fields. Value initialization and explicit reserved-field fixtures fix that defect. A second iteration rendered32 queues but exposed a marker race: `done` could appear after the broker read an earlier tail. The broker now consumes the marker's published byte count before checking final identities/counts. The saved32 fixture checks63,124 original entry/backend/AX/source descriptors plus256 refusals. Interrupted and obsolete test runs remain diagnostic history, not current validation.

Current-source live recovery completes32 original guarded returns,45,448 entry/AX/source descriptors and1,235 completed-canvas assertions with zero retained surfaces or viewport image uploads. Native warm34.98ms median/cold320.56ms and request-to-reply warm91.99ms excluding measured diagnostic assertions pass unchanged budgets. Both actual queue2 peer-death runs produce the expected terminal refusal, no final completion marker and private Wine cleanup; the fresh recovery session follows them. Independent precise original raster comparison is recorded separately below. Existing PE32 lifetime/NOACCESS/caller ABI guards remain unchanged. The adapter uses a finite diagnostic source journal; rendering queues beyond32 in a real original session, normal mode without diagnostic assertions, hardware live Qt/input/scanout and original simulation replacement are still distinct boundaries. Synthetic512-queue hardware results do not promote those stages.
