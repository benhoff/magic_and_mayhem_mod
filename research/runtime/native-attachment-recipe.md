# Native configured attachment preview

This extends the [selected mode-one contract](animation-mode-one-attachment.md)
with an installed configuration recipe. It is a bounded offline preview, not
native gameplay admission or a live replacement.

`apps/sprite-scene/attachment_recipe.cpp` loads encrypted
`CFG/Encrypted/effectani.cfg` through AssetFile and the native packed/config
readers, closes the handle, and resolves entry `ANI_36`. It owns its returned
path and selected values. Configuration input/decoded size is capped at 1 MiB.
The selected reference must be `EFFECTS` plus an index 0..12; the printer must
be `NORMAL`. Missing/invalid values and unsupported printers fail before export
creation. The application builds a bounded `Sprites/effectsN.ani` request;
the child SPR uses the ANI sibling basename and existing case-insensitive,
Windows-path AssetFile resolution. No original pointer or raw address enters
the widgets or native asset/renderer services.

Installed entry 36 yields **effects2.ani, sequence 40 + admission facing**.
`--attachment-facing 0..7` specifies that admission facing explicitly. Body
group/facing controls remain independent; no automatic child phase switch is
inferred. Admission is explicit in this preview rather than generated by a
recovered spell, equipment or creature action. The numeric mode is not assigned
a speculative gameplay name.

The scene applies the recovered first attachment composition and nonzero-health
visibility gate. Mode-one child ticks have no stopped-sequence restart from
`--loop`; other explicit layers retain their prior loop policy. Removing the
attachment stops and clears its player. Reentry restarts it; requesting an
already-entered mode leaves its phase alone. Child ticks remain independent
of health visibility. Missing parent/child display hides the layer as a native
safety policy. Layer order, unshaded embedded palette conversion, checkerboard
anchors, parent loop/clock and fully in-bounds rendering remain preview policies.

```bash
working/build/sprite-scene/mnm-sprite-scene-preview \
  --root working/game-clean --ani 'Creatures\redcap.ani' --sequences 0 \
  --attachment-mode-one --attachment-facing 0 --ticks 32 --loop
# Explicit lifecycle fixture: removal before tick 8, reentry before tick 16.
working/build/sprite-scene/mnm-sprite-scene-preview \
  --root working/game-clean --ani 'Creatures\redcap.ani' --sequences 0 \
  --attachment-mode-one --attachment-remove-at 8 --attachment-reenter-at 16 \
  --ticks 32 --loop --export-dir working/tests/new-attachment-recipe
python3 tools/test-attachment-recipe-scene.py
```

`--attachment-health` supplies the signed health fixture (default 1); zero
hides this recipe, negative values satisfy the original nonzero gate. It does
not change body gameplay/health behavior. Recipe selection and explicit
`--layer` inputs are mutually exclusive. Export metadata records configuration
entry, asset index, sequence, admission facing and health/transition fixtures;
per-frame records include child selection, raw events and draw anchors.

## Evidence and limits

The [retained report](native-attachment-recipe.json), from
`working/tests/attachment-recipe-scene/run-zb8idoz3`, verifies **14 runs / 462
complete native frames / 462 body states / 462 layer states**, all matching.
It covers all eight admission facings, the four footprint-size-2 views,
zero/negative-health visibility, removal/reentry and a looping parent. Window
smoke, mixed explicit-layer rejection and renderer cleanup pass.

The independent Python oracle decodes the installed configuration, executes
original attachment transitions and child controller traces, obtains separate
original body traces, and independently reads ANI offsets and SPR rows. It
checks every RGB565 pixel and expanded RGBA hash. This combines original
selection/control evidence, static drawing gates and independent native pixel
composition; it is not original whole-scene rendering or original configuration
loader execution. All source/input hashes are retained and unchanged during
the run. Original manifests pass before/after, including the earlier failed
oracle run: all 2,927 immutable files remain unchanged.

Six relevant CTests pass normally and under ASan/UBSan (leak detection disabled
in this environment); reset/ownership, malformed recipe references/printers,
health gates, no-op admission, removal/reentry and stopped-child loop behavior
are covered. The initial pixel oracle mistakenly used a neighboring entry's
base 50; the final oracle reads base 40 from entry 36 independently. That failed
run remains disposable evidence, not a reported success.

The existing explicit two-layer runner also passes at
`working/tests/animation-layers/run-rfpwf1iv`: 198 frames, 396 body states and
792 layer states, with original selection and independent pixels matching. Its
summary, source/input hashes and generated report hash are retained in the
recipe evidence alongside the new runs.

Complete attachment producer/lifecycle rules, other mode transitions, child
event consumers, world clock/positions, original sort/lighting and live
integration remain outstanding. This milestone establishes one actual
configuration-to-asset-to-controller-to-placement path within those boundaries.
